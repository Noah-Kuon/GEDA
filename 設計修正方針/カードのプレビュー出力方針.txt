カードのスクリーンショットボタンを押した際に、実際に表示させているカードと、アスペクト比の違う（カードに表示されている写真がゆがんだ状態）画像が下記だされてしまいます。まずは原因だけ究明し、解決案を提示してください。
原因を特定できました。
原因
「カードの高さ」の決まり方が、キャプチャ用に複製したDOM（clone）では再現されない仕組みになっているためです。
カードサイズ設定(表示設定の「比率」)の既定値は fit（画面にフィット） モードです（cardRatioMode = localStorage.getItem('kp_card_ratio_mode') || 'fit'）。
fit モードでは、applyCardRatio() が動的に注入するCSSにより、カードの高さは自分の幅から計算(aspect-ratio)されているのではなく、
 .grid-wrapper(flexコンテナ) → .grid-container { flex:1 } → .grid-item { height:auto }
 という**親からの引き伸ばし(stretch)**だけで決まっています。つまりカード単体では「自分が何pxの高さになるか」を知らず、.grid-wrapperに入って初めて高さが確定する仕組みです。
ところが doScreenshot() は target = document.querySelector('.grid-container') を cloneNode(true) した上で、.grid-wrapperから切り離して<body>直下に(position:fixed; top:-999999px)貼り付けています。この時点で .grid-container は元の flex 引き伸ばしの文脈を失うため、clone内の各カードの高さは「fitで引き伸ばされた実際の高さ」とは別物（多くの場合、内容に応じた自然な高さ＝実際よりかなり低い高さ）になります。
画像の歪み対策(object-fit:coverをcanvasで再現する処理)は、元のライブDOMのカード（正しい・引き伸ばされた高さ）を基準に「正しくクロップされた画像」を作成しています。しかしそのcanvasを挿入する先は、高さが変わってしまったclone側のコンテナであり、canvas自体は width:100%;height:100% で親に合わせて再度引き伸ばされるため、「正しい比率で切り抜いた画像」が「間違った比率の箱」に押し込まれて歪む、という二重の歪みが発生しています。
つまり、object-fit:coverをcanvasで再現する対策自体は正しく機能しているものの、その前提となるカードの高さ計測タイミングと、実際にcanvasが配置される箱のサイズが食い違っているのが根本原因です。既定モードの fit を使っている限り、ほぼ全ユーザーがこの症状に当たります（auto固定高や1:1等のaspect-ratio指定モードでは、高さが幅から自己完結的に決まるため症状が出にくいはずです）。
解決案（案のみ）
案A：clone前に各カードの実測サイズを固定値として焼き込む（推奨・影響範囲が最小）
 cloneNodeする直前に、元の .grid-item ごとの getBoundingClientRect() を測っておき、clone側の対応する .grid-item に style.height = 実測px を明示的にインラインで設定してから <body>に追加する。fitモードの「引き伸ばし」という“結果”だけを固定値としてcloneに複製するイメージで、ライブ側の挙動は一切変えません。
案B：.grid-container単体ではなく.grid-wrapperごとclone・計測する
 flexの親子関係を保ったままcloneすれば、flex:1による引き伸ばしがclone内でも自然に再現されます。ただしラッパー側のスクロールバー・パディング・他の兄弟要素の混入を避ける調整が追加で必要になります。
案C：キャプチャ時だけ一時的にfit用CSSをauto（固定高さ）相当に強制的に上書きし、キャプチャ後に戻す
 キャプチャ直前に card-ratio-style の内容を、その瞬間の実測高さに基づく固定pxのheight指定に一時的に差し替え、html2canvas実行後に元のCSSへ復元する。案Aに近い発想ですが、CSSレベルで対応する分、複数カード・全カードキャプチャ(captureMode:'full')時にも一括で効きやすい利点があります。
個人的には**案A（または案Aと案Cの併用）**が、既存のfitロジックに手を入れずに済み、リスクが一番小さいと考えます。方向性が決まれば実装します。
